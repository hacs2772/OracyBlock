# OracyBlock — 서비스 컨셉 & 개발 핸드오프

> **서비스명:** OracyBlock (오러시블록)  
> **메인 슬로건:** **Hear it. Say it. No reading required.**  
> **서브 슬로건:** **Build real conversations, block by block.**  
> **한국어 메시지:** **듣고, 말하고, 읽기 공부는 생략.**  
> **한 줄 소개:** 글자를 외우거나 쓰지 않고, 가상 상대와 실제처럼 듣고 말하며 브릭을 조립해 여행지 스몰토크를 준비하는 게임형 외국어 회화 서비스.

## 1. 기획 배경과 목표

- **출발점:** 일본 여행 중 이자카야 옆자리 사람과 짧게라도 대화를 나누고 싶다. 메뉴판이나 표지판은 사진 번역기로 읽을 수 있지만, 실시간 대화는 **듣고 바로 반응하고 말하는 능력**이 중요하다.
- **문제 인식:** 기존 언어 학습에서 문자 읽기·쓰기·맞춤법 훈련에 많은 시간을 사용한다. OracyBlock은 **실전 듣기·말하기만 빠르게 경험**하는 별도의 학습 경로를 제공한다.
- **최종 목표:** 완벽한 문법이나 유창함이 아니라, 여행지에서 인사하고, 질문을 알아듣고, 간단하게 답하고, 다시 질문하며 **자연스러운 스몰토크를 이어갈 자신감**을 얻는 것.
- **출시 순서:** **일본어 우선 → 영어·중국어 등 다국어 확장**. 웹사이트로 시작하고 이후 모바일 앱으로 확장.
- **브랜드 계열:** 기획 중인 **ASMRBlock**과 `*Block` 네이밍 및 **조립하는 브릭** 경험을 공유. 단, 두 서비스의 콘텐츠와 UX는 독립적이다.

## 2. 절대 지켜야 할 제품 철학

1. **Listen → Speak → Connect.** 먼저 상대방의 말을 듣고, 자신의 목소리로 답한 뒤, 대화를 이어간다.
2. **읽기·쓰기는 필수 학습 요소가 아니다.** 단어 철자 암기, 타이핑 정답, 문자 인식 시험, 읽기 퀴즈를 핵심 흐름에 넣지 않는다.
3. **음성이 주인공이다.** 학습은 가상 상대의 음성(TTS/녹음)을 듣고 마이크로 응답하는 방식으로 진행한다.
4. **실전 의사소통이 정답이다.** 발음·문법의 완벽함보다는 상대방이 이해할 수 있는지, 상황에 맞는지, 대화가 이어지는지를 우선한다.
5. **블록은 실제로 조립된다.** 평평한 사각형 카드를 단순히 쌓는 UI가 아니라, **윗면 돌기(stud)가 있는 3D 장난감 브릭이 맞물려 결합되는** 시각·촉각적 게임 경험이어야 한다.
6. **부담 없이 짧게.** 초보자가 하루 몇 분만 해도 인사 → 답변 → 되묻기까지 작은 성공을 경험하게 만든다.
7. **접근성은 유지한다.** 읽기 공부를 제외한다는 뜻이지 모든 UI 텍스트를 금지한다는 뜻은 아니다. 자막/스크립트/힌트는 **선택적으로 열 수 있는 보조 기능**으로 제공하되 음성 학습 화면에서는 기본적으로 숨긴다.

## 3. 핵심 학습 루프 (가장 중요)

**상황 선택 → 가상 상대가 말을 건다 → 사용자 음성 답변 → 상대가 반응·되묻기 → 성공 시 브릭 획득 → 브릭 결합 → 짧은 대화 완성**

- **상황 선택:** 이자카야, 카페, 숙소, 길 안내, 기차, 여행자 간 잡담 등.
- **듣기:** 상대방이 실제 말투와 속도에 가깝게 질문한다. 초반에는 느리게 재생하거나 다시 듣기 제공.
- **말하기:** 사용자가 마이크로 답한다. 타이핑 요구 없음.
- **반응:** 가상 상대는 사용자의 **의도**를 파악해 반응하고 후속 질문을 던진다. 오답 처리만 반복하는 단답형 퀴즈를 피한다.
- **게임 보상:** 이해/응답/질문 이어가기 등 작은 목표를 달성할 때마다 **브릭이 생성되어 착 붙는 조립 애니메이션**과 함께 쌓인다.
- **진척 표현:** 단어 암기 개수보다 **완성한 대화 체인, 연결한 턴 수, 경험한 상황, 반복 성공률**을 강조한다.
- **실수 허용:** 무응답·잘못 알아들음·발음 불명확할 때는 상대가 자연스럽게 다시 말하거나 쉽게 바꿔 말한다. 재시도를 실패 낙인 없이 지원한다.

### 일본어 MVP 대화 예시 (화면에는 기본적으로 문자 노출하지 않음)

1. 사용자가 `이자카야에서 첫 대화` 스테이지를 선택한다.
2. 가상 상대가 음성으로 “어디에서 오셨어요?”라고 묻는다.
3. 사용자가 일본어 음성으로 “한국에서 왔어요.”라고 답한다 → **답변 브릭 획득**.
4. 상대가 “일본 여행은 처음이에요?”라고 후속 질문한다.
5. 사용자가 답하고 “추천하는 음식 있어요?”라고 되묻는다 → **질문 브릭 획득**.
6. 대화가 3~5턴 자연스럽게 이어지면 브릭들이 서로 맞물려 **스몰토크 구조물 완성**.

> **품질 기준:** 정해진 문장 하나를 정확히 읽거나 따라 쓰는 학습이 아니다. 사용자의 여러 자연스러운 답변을 의미 기준으로 수용해야 한다.

## 4. 브릭 게임 디자인 (기존 네모 카드와 차별화)

### 시각 아이덴티티

- **정체성:** 레고를 연상시키는 **둥근 모서리의 입체적인 장난감 브릭**. 특정 완구 회사의 로고나 고유 상표 디자인을 그대로 복제하지 않고 독자적인 브릭 스타일로 제작한다.
- **필수 형태:** 상단 2~4개 원형 돌기(stud), 두께감, 측면 명암, 살짝 비스듬한 **아이소메트릭(isometric) 뷰**, 연결될 때의 스냅/찰칵 느낌.
- **금지할 인상:** 단순 직사각형 카드를 수직으로만 나열한 대시보드, 지나치게 기업형인 학습관리시스템(LMS), 빽빽한 텍스트 중심 퀴즈.
- **브릭 종류(예시):** `듣기 브릭` / `응답 브릭` / `되묻기 브릭` / `리액션 브릭` / `스몰토크 완성 브릭`.
- **보상 애니메이션:** 브릭 등장 → 방향 정렬 → 기존 브릭 위에 내려앉음 → 살짝 탄성 있는 스냅 → 대화 구조물 성장.
- **사운드:** 짧고 기분 좋은 결합음과 완료 효과음. 음성 대화에 방해되지 않아야 하며 소리 끄기 제공.

## 5. 메시지·카피 가이드

**메인:** `Hear it. Say it. No reading required.`  
**서브:** `Build real conversations, block by block.`  
**대안 광고 문구:** `Talk to people, not textbooks.` / `Skip reading. Start speaking.`  
**한국어:** `듣고, 말하고, 읽기 공부는 생략.` / `글자는 몰라도, 대화는 시작할 수 있어요.` / `귀로 익히고, 입으로 연결하고, 브릭으로 쌓는다.`

**표현 유의:** '독해 수업이 없다'와 '읽기 능력이 언어 학습에 전혀 필요 없다'는 다른 주장이다. 제품은 **읽기를 필수로 요구하지 않는 실전 회화 경로**를 제공한다는 의미로 소통한다. 모든 대화·상황에서 유창함을 보장하지 않는다.

## 7. MVP 우선순위

### 필수 (1차 웹 프로토타입)

- 일본어 학습 / 한국어 사용자 인터페이스.
- 이자카야·카페·간단한 자기소개 등 **3개 내외의 짧은 회화 상황**.
- 가상 상대의 음성 질문 재생 및 다시 듣기.
- 마이크 입력과 음성 인식(STT), 발화 의미/의도에 대한 유연한 판정.
- 정해진 흐름 + 후속 질문을 통한 최소 **3~5턴 대화**.
- 성공 시 실제 브릭이 조립되는 애니메이션과 간단한 진행 상황 저장.
- 자막/텍스트 힌트 **기본 숨김, 필요 시 표시**.
- PC·모바일 웹 반응형 디자인, 마이크 권한 안내, 오류·재시도 UX.

### 이후 단계

- 자유 대화형 AI 캐릭터, 다양한 캐릭터 성격과 억양.
- 음성 기반 미니게임, 대화 콤보/연속 성공/성취 배지.
- 개인 맞춤 약점 복습, 여행 직전 집중 모드.
- 영어·중국어 등 언어 팩 추가.
- 네이티브 또는 크로스플랫폼 모바일 앱, 이어폰 중심 사용성.

### MVP에서 제외

- 히라가나/한자/알파벳 시험, 받아쓰기·철자·타이핑 필수 퀴즈.
- 과도한 문법 설명과 교재식 콘텐츠.
- 복잡한 결제·랭킹·SNS 기능.
- 처음부터 대규모 오픈월드/고사양 3D 게임 구현.

## 8. 개발 설계 시 고려사항

- **오디오 파이프라인:** 사용자 발화 녹음 → 음성 인식(STT) → 상황·의도 평가/대화 상태 관리 → 상대 응답 생성 → 음성 합성(TTS). 초기에 품질 검증 가능한 API 기반 구조로 시작 가능.
- **상태 모델 예시:** `language`, `scenario`, `stage`, `conversationTurn`, `intent`, `retryCount`, `earnedBricks`, `completedChains`.
- **콘텐츠 구조:** 국가/언어에 의존하지 않는 공통 대화 엔진 + 언어·상황별 콘텐츠 데이터 분리.
- **프론트엔드:** 웹 우선, 모바일 우선 반응형 UI. 브릭은 CSS 3D나 경량 WebGL/Three.js 등으로 구현하되 **저사양 폰에서도 부드러운 경험**이 중요.
- **안전·프라이버시:** 마이크 권한은 사용 시점에 요청하고, 녹음 저장 여부 및 보존 정책을 명확히 한다. 사용자 음성 데이터를 무조건 장기 저장하지 않는다.
- **접근성:** 자막/반복 재생/속도 제어/명암 대비 제공. 음성 사용이 불가능한 환경에서는 일시 중지·이어하기 지원.
- **브랜드 검증:** `OracyBlock`의 상표·유사 서비스명·도메인·앱스토어 이름은 실제 출시 전에 별도 확인. 아직 확보된 것으로 간주하지 않는다.

## 9. 구현 완료 판단 기준 (1차 데모)

- [ ] 사이트 접속 후 1~2번의 주요 선택으로 첫 일본어 대화를 시작할 수 있다.
- [ ] 일본어 글자·철자를 **읽거나 입력하지 않고** 3턴 이상 회화를 진행할 수 있다.
- [ ] 가상 상대의 음성을 듣고 마이크로 실제 답변할 수 있다.
- [ ] 답변이 정확한 문장 암기가 아니어도 의미가 통하면 진행된다.
- [ ] 성공할 때마다 **입체 브릭이 기존 브릭에 맞물려 쌓이는 화면**이 확인된다.
- [ ] 한 상황을 마치면 완성한 브릭 구조물과 다음 단계가 명확히 보인다.
- [ ] 모바일 웹에서도 마이크·오디오·조립 효과를 사용할 수 있다.
- [ ] 메인 슬로건에서 **읽기 학습이 필수가 아니라는 차별점**이 즉시 드러난다.
